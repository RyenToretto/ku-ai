# UI/UX Pro Max — 最佳实践

## 何时使用

- 项目初期选择设计方向（从 67 种风格中找到最匹配的）
- 需要完整设计系统但没有设计师资源
- 想要基于产品类型自动匹配色板和字体
- 需要检查 UX 反模式和无障碍问题

## 何时不用

- 项目已有完整 Figma 设计系统，此时用 DESIGN.md 导出更精准
- 商业项目（CC-BY-NC-4.0 禁止商业使用，确认许可授权后再使用）
- 只需要代码逻辑，对 UI 样式无要求

## 许可证合规

> ⚠️ 重要：CC-BY-NC-4.0 禁止商业使用

| 场景 | 是否可用 |
|------|------|
| 个人学习、Demo 项目 | ✅ |
| 开源非营利项目 | ✅ |
| 内部工具（公司内部使用，不对外销售） | 需确认 |
| 商业 SaaS 产品 | ❌（需另行授权） |
| 客户付费项目 | ❌（需另行授权） |

## 组合使用建议

| 组合 | 效果 |
|------|------|
| ui-ux-pro-max → DESIGN.md | 用 ui-ux-pro-max 探索和选定设计方向，再将选定的令牌导出为 DESIGN.md 固化 |
| ui-ux-pro-max + taste-skill | 双重保障：ui-ux-pro-max 提供数据库检索，taste-skill 约束输出行为 |
| ui-ux-pro-max + impeccable | ui-ux-pro-max 选定风格，impeccable 对实现结果进行专业审计 |

## 版本管理

- 定期运行 `uipro update` 获取最新的数据库更新（风格、色板会持续增加）
- 团队项目建议用 `uipro init --offline` 固定版本，保证所有成员一致
- 可在 `.gitignore` 中排除 Skill 文件，避免提交到版本控制

## 常见风险

| 风险 | 应对方式 |
|------|------|
| 忽略许可证在商业项目中使用 | 使用前确认项目性质；商业项目改用 MIT 授权的替代方案 |
| 数据库过大导致上下文占用过多 | 只查询需要的域（product/style/color），不全量加载 |
| Agent 推荐的设计方向与品牌不符 | 在请求中明确品牌关键词和约束条件 |
| 生成的色板缺乏对比度 | 明确要求符合 WCAG AA 对比度标准 |
